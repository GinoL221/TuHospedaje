# Document the project: backend architecture, HTTP API and frontend

Derived from three read-only inventories run on 2026-11-12 against `main@ffd65be`. No behaviour change except the OpenAPI annotations, which are corrected to match the code.

## Specs

- **S1.** `docs/markdown/api-reference.md` lists every handler under `backend/src/main/java/com/tuhospedaje/controller/` — 49 of them — with HTTP method, full path, access rule and the place that grants it, request type with its validation, response type, and every HTTP status the code path can actually return with the source of each (annotation, thrown exception, `ResponseEntity`).
- **S2.** The same file carries the error mapping (condition → status → body fields → message key), and the cross-cutting sections a consumer needs: cookie authentication, CSRF, pagination defaults, `Retry-After`, and locale resolution through `Accept-Language`.
- **S3.** It states no endpoint or status the code cannot produce. Concretely: the `404` on `POST /api/ratings` is documented as unreachable rather than promised, and the statuses the annotations omit today (`400` for category in use, `400` for a lodging with reservations, `400` for pagination, `403` for CSRF, `429` on login) appear in the reference.
- **S4.** OpenAPI agrees with the reference: no `@ApiResponse` for an error status uses `content = @Content`; `POST /api/auth/welcome-email/resend` and `GET /api/lodgings/recommendations` carry `@Operation` and `@ApiResponses`; the `csrfToken` scheme is not declared on `GET` handlers; and the API version has a single source instead of the literal `1.0.1` in `OpenApiConfig`.
- **S5.** A backend integration test fails when the generated spec carries an operation that `api-reference.md` does not list, and when OpenAPI documents a status that the markdown omits. The markdown is the readable layer; the test is what stops it from drifting.
- **S6.** `docs/markdown/backend-architecture.md` documents the package layout, the request flow with the filters in their real order (`authRateLimitFilter` and `refreshRateLimitFilter` before `jwtAuthenticationFilter`), the three locking strategies and why the pessimistic lock targets the `Lodging` row, refresh token families with reuse detection, the email outbox lease and `REQUIRES_NEW` writes, and the rate-limit key dimensions. `project-definition.md` and the sprint reports link to it instead of repeating the four-layer diagram.
- **S7.** The stale claims found by the inventories are corrected: constructor injection and `toEntity()` in `project-definition.md`, the `ServiceImpl implements interface` rule, the security report's request flow, the Spring Boot version in `sprint-4-report.md`, the Cloudinary references in the audit, the `400` expectations and Bearer-token assumption in `sprint-2-test-plan.md`, the self-declared historical `current-main.md` listed as a delivery entry point, and the orphan `offline-safetyunit.md` missing from the `docs/README.md` index.
- **S8.** Frontend docs match the tree: `frontend/README.md` covers `src/test/`, `src/assets/`, `src/styles/`, where each guard redirects, and that `/admin` passes through `RequireAdmin` before the shell; `DESIGN.md` lists every component and route that exists under `frontend/src`.
- **S9.** Out of scope: writing tests for the untested frontend pieces, localizing the remaining hardcoded messages (#456), and every other open issue (#454, #455, #457).
