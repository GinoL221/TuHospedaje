## Objective
Standardize a repeatable, version-matched Playwright browser matrix for vetted public checks against the preserved academic demo, and document the boundary separating that matrix from state-mutating E2E.

## Problem and constraints
- `e2e/package.json` pins Playwright 1.60.0; the official matching Noble image is already cached. WebKit lacks host libraries on CachyOS; the pinned image ran a bounded WebKit check successfully.
- `e2e/playwright.config.js` has Chromium, Firefox and mobile Chromium but no WebKit project. `README.md` originally recommended an unrestricted `npx playwright test`, while auth, booking, reviews and admin CRUD can write to the database.
- Keep the existing academic Compose containers, host MariaDB, seeded volumes, and pre-existing AUR source files untouched. No push, teardown, broad upgrades, system package installation, or tests that write application data. Do not alter CI or the full E2E suite in this unit.
- Preserve pre-existing untracked academic evidence and worktree state. The user authorized one scoped local commit for this runner and guide after final smoke verification; no push is authorized.

## Delivery strategy and scope
One reviewable public-runner unit, estimated below 400 authored diff lines. New isolated public config with an explicit file allowlist, fixed projects (desktop Chromium, Firefox, WebKit), and a launch command that only accepts this preset. Use the already-cached official image matched to the pinned npm version, without pulling; read-only project mount, ephemeral container, unprivileged process, no Docker socket, no new published ports, bounded resources, separate private artifacts. Restrict the demo run to public navigation/GET scenarios. README gets a short quick path and a clear link or section on stateful tests. A future disposable E2E stack/CI WebKit expansion is out of scope.
